# Python dependencies for the Ask CK server-backed workbench (ask-ck/CK-main).
# Install with:  pip install --user -r ask-ck/CK-main/requirements.txt
# (setup.sh installs these into the repo .venv and also builds ck.db.)
#
# Versions below are lower bounds known to work as of 2026-07-16.
#
# Requires Python >= 3.10 (fastapi>=0.139 drops 3.9). setup.sh enforces this and
# will pick the newest python3.1x on PATH; installing manually on Python 3.9 or
# older fails with "No matching distribution found for fastapi".
#
# PREFER PYTHON 3.13 — match the testbox (tb470 runs 3.13.5). The PyTest Creator
# lints GENERATED scripts with `py_compile` using THIS interpreter, while those
# scripts run under the testbox's python3. A mismatch lints the wrong language
# version: it accepts imports the target removed (this is how a `distutils`
# import, gone in 3.12, once shipped to a 3.13 testbox) and rejects syntax the
# target accepts. See README -> "Python version: match the testbox".

# --- Core server (required to boot; keyword search works with just these) ---
fastapi>=0.139
uvicorn>=0.46
jinja2>=3.1
requests>=2.34
python-multipart>=0.0.9
pydantic>=2.9

# --- Testbox execution (PyTest Creator step "6. Run") ---
# pt_exec.py's SSH/SFTP runner. It was used from the day that feature landed but declared
# in NO requirements file — PLAN-pytest-creator.md merely noted "paramiko 2.9.3 is
# installed", which was true of one machine, not of a fresh venv. The gap survived because
# the failure is polite and far from the cause: `import paramiko` sits inside
# pt_exec._connect(), so the server boots, every other tool works, and the profile probe
# just answers {"ok": false, "detail": "SSH connection failed: No module named 'paramiko'"}
# — which reads as a testbox/network problem, not a missing dependency.
paramiko>=3.4

# --- Py2 -> Py3 fragment translation (PyTest Creator "4. Fragments", D3) ---
# The legacy corpus is Python 2, so reused fragments are modernized deterministically
# before they reach Generate. That used the stdlib's lib2to3 — which Python 3.13 REMOVED,
# and 3.13 is the version this file tells you to prefer (see the note at the top: the
# generated scripts are linted with THIS interpreter and the testbox runs 3.13.5). So the
# recommended environment was exactly the one where the feature silently stopped working:
# `_translate_py2` returned status "unavailable" and every Py2 fragment shipped
# untranslated behind a soft-warn, with nothing raising to say so.
# fissix is the maintained fork of lib2to3 — same `refactor` API, own `fissix.fixes`
# package — so pytest_create._py2_refactor_backend prefers stdlib lib2to3 where it still
# exists and falls back to this. Without either, translation degrades (it never crashes),
# which is why this was invisible for so long.
fissix>=24.4.24

# --- PEP 8 style checking of GENERATED scripts (PyTest Creator "5. Generate" -> Lint) ---
# A RUNTIME dependency, not a dev one: the server itself lints the scripts it generates
# (routers/pytest_create._pep8_findings), so this must be present wherever the server runs,
# not merely wherever the tests run. Pure Python, zero dependencies, works offline.
#
# It degrades rather than crashing -- a missing pycodestyle makes the lint emit
# "style NOT checked" instead of silently reporting a clean style pass. That distinction is
# the point: the same shape (a check that could die and still lint green) is exactly what
# Phase 7.7 had to fix in the coverage check.
pycodestyle>=2.11

# --- Semantic / hybrid search (Stage D; the server degrades to keyword without them) ---
# ALL THREE BELOW ARE REQUIRED for semantic/hybrid search and the offline embedding
# model. They are easy to miss when building a venv by hand: the server still BOOTS
# without them and silently answers keyword-only. Verify after any manual venv build:
#   PYTHONNOUSERSITE=1 .venv/bin/python -c "import sentence_transformers, sqlite_vec"
#   curl -s localhost:8000/health   # sqlite_vec_loaded: true, embeddings: ~83816
# torch is CPU-only for this app. A bare `pip install torch` on Linux pulls the
# large CUDA build — prefer the CPU wheel:
#     pip install --index-url https://download.pytorch.org/whl/cpu torch
# setup.sh does this automatically (CPU wheel first, then the rest).
sqlite-vec>=0.1.6
sentence-transformers>=3.0
torch>=2.2
# sqlite-vec needs a SQLite built with enable_load_extension. If the runtime
# Python's stdlib sqlite3 lacks it (e.g. macOS system Python), install this
# self-contained build (Linux/most wheels); db.py auto-prefers it. Vector search
# just degrades to keyword when neither is available — never a startup failure.
pysqlite3-binary>=0.5; platform_system == "Linux"
