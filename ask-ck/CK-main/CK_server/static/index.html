Welcome to Ask CK

Ask CK is a server-backed test-engineering workbench for the AWPTCM test-case program. It brings the tools for enriching manual test cases, mapping them to automation, and turning them into runnable scripts into one place. Pick a tool from the sidebar, or read the step-by-step guides below. Most tools use an LLM via a local subscription CLI — set that up first under LLM → Configure.

Tool guides (inverse order of the sidebar list)
Objective / Test Case Generator
The original Ask CK tool. Turns a sparse AWPTCM manual case into a refined case with declarative objectives, Zephyr-ready test steps, and traceability — with a review gate at every step.
  1. 1. Cases — pick a case from the Open/partial or Complete dropdown and Load it.
  2. 2. TestLink — review the primary decision and candidate historical cases; Search or Suggest with the LLM, then Confirm your selections.
  3. 3. Zephyr — review related external Zephyr cross-references; Confirm.
  4. 4. ATPyLib (scored) — review the scored automation-coverage candidates and Confirm which ART suites apply.
  5. 5. Objectives (LLM) — synthesize the declarative objective artefacts from the confirmed reviews; edit, then Confirm.
  6. 6. Test Steps (LLM) — synthesize the Zephyr test steps from the finalized objective, then Export the Repeatable Bundle — this writes traceability.md + zephyr_payload.json into refined-cases/<Group>/. A case becomes "Complete" once this exists.
PyTest Creator
Turns a Complete case (one exported by the Generator above) into a runnable Allied Telesis framework (ATTestSet/ATTestCase) test script, then runs it on real hardware and iterates until it passes. Each step has a Confirm gate.
  1. 1. Cases — pick a Complete case and Load it (use ↻ Refresh list after exporting new cases in the Generator).
  2. 2. Sequence — the LLM extracts a prescriptive sequence of automatable steps from the refined case; edit the rows, Save, then Confirm.
  3. 3. Script Search — search the script databases (testsuites_art / svt_scripts / test_scripts) for scripts that do all, some, or none of the sequence; tick what to reuse, then Confirm.
  4. 4. Fit Decision — decide whether the sequence fits an existing script (reuse / extend) or needs a new one; Confirm.
  5. 5. Fragments — gather reusable code from the selected scripts (resolved to real source), untick what you don't want, then Confirm.
  6. 6. Generate — the LLM composes the script from fragments + gaps; edit the Group/name, Lint, Save to generated/<Group>/, then Confirm.
  7. 7. Run — pick a stored testbox (or add one under Testboxes), choose the .setup, and run it over SSH; results are parsed into per-TestCase PASS/FAIL.
  8. 8. Validate — Final Validation passes when every TestCase is PASS with zero failures. On failures, Fix with LLM loops back to Generate; promotion into testsuites_art/ is manual.
First-time setup: build the script index with tool/build_script_index.py, and add a testbox under the Testboxes sidebar item.

LLM Provider Login
Use your own locally logged-in subscription — Grok CLI (SuperGrok / X Premium+) or the Claude Code CLI on your own machine. No developer API keys. Apply / Login saves the workspace default; it is applied to cases as they load. On a shared Ask CK server, the Claude option runs against your own Claude seat via the local agent — seats are never shared.
Claude Code CLI — via your local agent (per-user, unshared)

On a shared Ask CK page, the server never runs claude. Instead, a tiny agent on your own machine runs it against your own Claude login, brokered through this browser tab. Your seat is never shared with other users, and the server never sees your credentials.

1. On your machine, install Claude Code (anthropic.com/claude-code) and run claude → /login.
2. Start the agent: cd ask-ck/agent && ./run-agent.sh (leave it running). See ask-ck/agent/README.md.
3. Click "Check my local agent" to confirm it's reachable and logged in.
4. Click "Apply / Login". Leave Model blank to use the CLI's default.

Usage counts against your own Claude seat's limits. If a call fails, make sure the agent is still running and you're logged in.
Grok CLI — Headless Mode (SuperGrok / X Premium+ Subscription)

Synthesis calls run through the local grok CLI using its OAuth login. No xAI API key is entered here.

1. Ensure the grok CLI is installed (commonly at ~/.grok/bin/grok).
2. In a terminal run grok login --oauth (or grok login) and complete the browser OAuth with your subscription account.
3. Click "Check Grok CLI" to verify.
4. Select the option and click "Apply / Login". Leave Model blank for CLI default.

Usage counts against your SuperGrok / X Premium+ subscription.

PyTest Creator — Cases
Pick the completed case to generate pytest code for (only cases with a refined zephyr_payload.json are listed). Selection here is independent of the Generator's loaded case. Use Refresh after exporting new cases in the Generator.
PyTest Creator — 2. Sequence Confirmed
Identify the prescriptive sequence of automatable test steps from the refined case, review/edit, then confirm.
PyTest Creator — 3. Script Search Confirmed
Check the script databases (testsuites_art / svt_scripts / test_scripts) for scripts that do all, some, or none of the sequence. Two ways to find matches — a plain keyword search, or an LLM suggestion from the sequence. Tick the ones to carry forward, then confirm.
Keyword search
Plain index search — no LLM. Matches script names, tags, and summaries.
LLM suggestion
Ranks the databases against your confirmed sequence and judges coverage. The guidance below is added to this request (and nudges pre-ranking) — use keywords, not sentences.
PyTest Creator — 4. Fit Decision Confirmed
Would the sequence fit cleanly into a selected script (reuse/extend), or is a new script needed?
PyTest Creator — 5. Fragments Confirmed
Re-use real code from the selected scripts: the LLM proposes symbols; the server resolves them to actual source. Untick anything not worth carrying, then confirm.
PyTest Creator — 6. Generate Confirmed
Generate the composite framework script (reused fragments + LLM for the gaps). Adjust the output naming, review/edit the code, lint, save, then confirm.
