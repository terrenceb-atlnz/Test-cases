Welcome to Ask CK

Ask CK is a server-backed test-engineering workbench for the AWPTCM test-case program. It brings the tools for enriching manual test cases, mapping them to automation, and turning them into runnable scripts into one place. Pick a tool from the sidebar, or read the step-by-step guides below. Most tools use an LLM via a local subscription CLI — set that up first under LLM, Configure.

Set up your seat for Claude (one time)
Set up your seat for Claude
Ask CK runs in your browser; it cannot run Claude on your PC by itself. A small agent on your PC does that, using your own Claude seat — nothing is shared and the server never sees a credential. One line installs Claude Code if needed, fixes your PATH, logs you in, installs the agent and starts it. Re-run the same line any time to update or repair.
  1. Windows — open PowerShell and paste:
    irm http://…/setup/setup.ps1 | iex (or download setup.ps1 and run it with powershell -ExecutionPolicy Bypass -File setup.ps1)
  2. Ubuntu — open a terminal and paste:
    curl -fsSL http://…/setup/setup.sh | bash (or download setup.sh)
  3. It asks once whether the agent should start when you log in, then opens Ask CK, which runs the final check itself — the result appears under LLM, Configure. Pick Claude Code CLI (my local machine) there and you are ready.
Manual route and details: ask-ck/agent/README.md. Later, Check My Local Agent under LLM, Configure also updates the Claude CLI on your PC.
Tool guides (inverse order of the sidebar list)
Objective / Test Case Generator
The original Ask CK tool. Turns a sparse AWPTCM manual case into a refined case with declarative objectives, Zephyr-ready test steps, and traceability — with a review gate at every step.
  1. 1. Cases — pick a case from the Open/partial or Complete dropdown and Load it.
  2. 2. TestLink — review the primary decision and candidate historical cases; Search or Suggest with the LLM, then Confirm your selections.
  3. 3. Zephyr — review related external Zephyr cross-references; Confirm.
  4. 4. ATPyLib (scored) — review the scored automation-coverage candidates and Confirm which ART suites apply.
  5. 5. Objectives (LLM) — synthesize the declarative objective artefacts from the confirmed reviews; edit, then Confirm.
  6. 6. Test Steps (LLM) — synthesize the Zephyr test steps from the finalized objective, then Export the Repeatable Bundle — this writes traceability.md + zephyr_payload.json into refined-cases/<Group>/. A case becomes "Complete" once this exists.
PyTest Creator
Turns a Complete case (one exported by the Generator above) into a runnable Allied Telesis framework (ATTestSet/ATTestCase) test script, and saves it to generated/. Each step has a Confirm gate; confirming 5. Generate saves the script and ends the Creator.
  1. 1. Cases — pick a Complete case and Load it (use Refresh List after exporting new cases in the Generator).
  2. 2. Sequence — the LLM extracts a prescriptive sequence of automatable steps from the refined case; edit the rows, Save, then Confirm.
  3. 3. Script Search — search the script databases (testsuites_art / svt_scripts / test_scripts) for scripts that do all, some, or none of the sequence; tick what to reuse, then Confirm.
  4. 4. Fragments — gather reusable code from the selected scripts (resolved to real source), untick what you do not want, then Confirm.
  5. 5. Generate — the LLM fills the standardized skeleton template from the fragments + gap-fill; Lint and Review it, then Confirm — which saves it to generated/<Group>/ and asks whether to test it in Validation (Test Composer section).
First-time setup: build the script index with ask-ck/tools/build_script_index.py.

Claude Code CLI — via your local agent (per-user, unshared)

On a shared Ask CK page, the server never runs claude. Instead, a tiny agent on your own machine runs it against your own Claude login, brokered through this browser tab. Your seat is never shared with other users, and the server never sees your credentials.

1. On your machine, install Claude Code (anthropic.com/claude-code) and run claude, then /login.
2. Start the agent: cd ask-ck/agent && ./run-agent.sh (leave it running). See ask-ck/agent/README.md.
3. Click "Check My Local Agent" to confirm it is reachable and logged in.
4. Click "Save Changes". Leave Model blank to use the CLI's default.

Usage counts against your own Claude seat's limits. If a call fails, make sure the agent is still running and you are logged in.

PyTest Creator — Cases
Pick a case to generate pytest code for (only Generator-Complete cases with a refined zephyr_payload.json are listed). Open/Partial = no script saved yet; Complete = its script is saved to generated/ (Validation's Finalize then removes the case from both lists). Selection is independent of the Generator's loaded case. Use Refresh after exporting new cases in the Generator or confirming one here.
PyTest Creator — 2. Sequence Confirmed
The refined case's test steps are shown first (the "before"). Extract Sequence asks the LLM to convert them into a prescriptive, runnable execution order (the "after") — the from column links each extracted row back to its source step so any re-sequencing is visible. Review/edit, then confirm.
PyTest Creator — 3. Script Search Confirmed
Find reusable scripts per sequence step so it is clear every step is covered. Page through the steps; for each, use its own Suggest (LLM) or keyword search to find scripts and choose the ones to reuse. Each step shows whether it is covered or has a gap. Save, then confirm.
PyTest Creator — 4. Fragments Confirmed
Re-use real code from the selected scripts, reviewed per sequence step. Gather Fragments (LLM) proposes, for each step, the fragment(s) worth reusing (green) plus the redundant alternatives it was preferred over (red, nested below) — so the accounting of every candidate is visible. Page through the steps; tick a fragment to include it in Generate (untick a green one or tick a red one to override). Save, then confirm.
Assembled artefact preview — the Generate skeleton with your selected fragments slotted per step (click to expand)

PyTest Creator — 5. Generate Confirmed
Generated one unit at a time — a unit is a single TestCase class, or the TestSet setup pair. The frame (imports, TestSet, the ts.add_testCase() runner) is rendered here, not by an LLM, so it cannot vary between units. Page through the units: each shows the prompt that will be sent (editable — the button sends what you see) and the code that came back. Summary assembles them locally, lints, and runs the holistic review.
Summary — assemble the generated units into one script and check it. Blue buttons call the LLM; the rest run locally.
  1. Assemble + lint — splice the units into the frame, re-stamp provenance, manifest-check + py_compile/PEP-8. Clear a red lint before moving on.
  2. Review (LLM) — read the assembled script for logic defects the linter cannot see (a verdict not matching its step, cross-unit inconsistencies). Findings only — no rewrite.
  3. Save to generated/ — write the file to disk.
  4. Confirm Step 5 — needs a clean lint (syntax errors cannot be overridden); saves the script to generated/ and ends the Creator. House-rule errors and a coverage gap ask for your acknowledgement first.
If something is wrong  ·  Re-lint re-checks the current script after a hand-edit (local, no re-assemble). Fix Units (LLM) re-generates only the units the lint errors or review findings name, under the cached shared half. A review-driven fix is HELD with a diff on the unit's page (held) for you to Save or Discard; a lint-only fix applies itself. It re-assembles and re-lints for you, so re-Assembling after it is redundant, not harmful. Fix Whole Script (LLM) rewrites the whole file — for findings that name no unit. Do not re-Assemble after THAT one (it re-splices the units and discards the rewrite): Re-lint / Review, then Save and Confirm. Grey buttons run locally; blue ones call the LLM.
