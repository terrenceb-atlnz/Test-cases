*(The batch began 2026-07-30 and ran across several usage windows; this record was completed and
committed 2026-08-03. Dates inside refer to when each measurement was taken.)*

**Task:** for the 10 "Not Executed" AWPTCM cases, create objectives + refined test cases +
pytest scripts using Opus, run judges, and attempt to run them on the bench.

**Headline:** objectives and refined test cases are **done for all 10 and all validate**. Pytest
generation is **blocked by a hard output-token ceiling**, quantified below and now gated so it
fails honestly instead of silently. Twelve latent product defects were found and fixed on the
way; three of them had been silently corrupting output, and one had made the entire testbox-run
feature dead on any fresh install.

## 2. Decisions made (and why)

| # | Decision | Reasoning |
|---|---|---|
| 1 | Drive the pipeline **through the running server**, not by calling Opus directly | The prompts, CLI grounding, coverage gate, skeleton and lints *are* the product. A direct model call would have tested the model instead of the pipeline. |
| 2 | Use `claude_code` auth (headless `claude -p`) as the Opus transport | The only headless Opus path: `claude_agent` needs a browser session and 502s from a script. |
| 3 | Pin **`claude-opus-5`** explicitly, not the `opus` alias | On this seat the alias resolves to `claude-opus-4-8`; the explicit id is also cheaper per call (11.7k vs 29.9k cache-creation tokens). |
| 4 | Write a reusable driver (`tool/pt_autopilot.py`) rather than ad-hoc curl | Ten cases × ~7 gated steps, resumable across session limits; re-running skips completed steps. |
| 5 | Substitute each review step's **own LLM suggestion** for the reviewer's click, capped at 8 rows, and record that it happened | The gates are human by design; the output must be honest about being machine-reviewed. |
| 6 | Use the **real `ck.db`**, not a scratch copy | This is genuine user traffic producing artefacts that were asked for. Real traffic is supposed to dirty it; only tests must not. |
| 7 | Acknowledge coverage gaps when the gate fires, but **record the gate's exact complaint** | An override must be a recorded choice, never a silent pass. |
| 8 | **Stop the batch twice** mid-run rather than let it finish | Each case was failing identically at $2–5. Two aborts saved roughly $40 of repeat failures. |
| 9 | Clear and redo all pre-fix PyTest sessions | The agentic transport had silently corrupted fragments (D8); artefacts from before the fix could not be trusted, and "probably fine" is not a standard. |
| 10 | Fix the transport defects found on the way instead of working around them | Every one of them would have hit any user of the Claude path, not just this batch. |
| 11 | Add a **size gate** rather than silently truncating, with an explicit override | Matches this router's existing coverage-gate pattern; converts four confusing symptoms into one honest, free failure. |
| 12 | Trim one case's sequence to prove the chain end-to-end, and **enumerate every dropped step** | Complete scripts are unreachable single-shot. A labelled pipeline proof beats "nothing ran" — and a silently shortened test that still reports PASS is the exact failure the coverage gate exists to prevent. |
| 13 | **Do not** hand-edit generated artefacts to make them pass | An edited script would not represent the pipeline's output, which is the only thing worth measuring. |
| 14 | Do **not** run judges or hardware against non-compiling scripts | Would have manufactured meaningless scores. |
| 15 | Leave the ceiling itself **unfixed** | Closing it means chunked generation (architecture) or capping steps (trades away objective coverage). Both are Terrence's call, not a default to pick quietly. |
| 16 | Restore the workspace LLM default to `local_llm`/`vllm-fast` at the end | It is a workspace-wide setting the browser UI also reads. |

## 3. The blocker: a hard, variable output ceiling

Full analysis in `../FINDINGS-generation-size-ceiling.md`. In short:

- The output cap is **32,000 tokens**, shared between **thinking and the answer**, and is not
  raisable (`CLAUDE_CODE_MAX_OUTPUT_TOKENS=64000` leaves it at 32,000).
- `--max-thinking-tokens` caps a **single thinking block, not the total**. Measured with a 2,048
  cap in force: 34,966 total output tokens of which the answer was only ~14,575 — about
  **20,400 went to thinking anyway**. So the room left for the answer **varies run to run and
  cannot be computed in advance.**
- Generated Python measures **2.89 chars/token**; a filled TestCase runs **4,700–5,500 chars**.
- Working ceiling: **~9–20 TestCase classes**, depending on how much thinking a run consumes.

Three measurements on the same case, which is the clearest way to see it:

| Sequence steps | Delivered | TestCases | Complete? |
|---|---|---|---|
| 44 | 86,644 chars | 21 of ~40 | no — truncated mid-string |
| 21 | 88,593 chars | 16 of 17 | no — truncated but **parsed cleanly** |
| 15 | 42,122 chars | 9 of 11 | no — truncated mid-comment |
| 13 (6 verify) | 37,744 chars | **6 of 6** | **yes** |

Note rows 1→2: **trimming did not shrink the answer** — the model writes to fill the budget, so
it just became more verbose per TestCase. And row 3 fell to half the budget purely because
thinking took more that run.

**The failure mode to fear** is row 2: a script that truncates on a statement boundary, so
`ast.parse` succeeds and it looks finished. Only the logging-contract lint and the missing
`ts.run(sys.argv)` revealed it. Valid Python that silently tests less than it claims.

### Recommended next step

**Split large refined cases into several smaller ones.** It preserves total coverage across the
set, needs no architecture change, and each piece then fits. Chunked generation is the only
thing that truly removes the ceiling but is real work. Capping steps in the Generator is
cheapest and worst — it silently trades away the coverage the objective-coverage gate exists to
protect.

## 4. Defects found

All fixed and mutation-tested unless marked OPEN. **36 mutations attempted, 36 caught.**
Gate after: **775 pytest** (was 719) **+ 92 Vitest, ck.db signature unchanged.**

| # | Defect | Impact |
|---|---|---|
| D1 | `extract_sequence` passed no `timeout`, inheriting `run_prompt`'s 180s while every sibling asked 300–600s | Deterministic death on any rich case; the 502 text blames the LLM, not the missing kwarg |
| D2 | Every caller timeout was sized for the **streaming** vLLM path, where the number bounds the gap *between chunks*; a CLI subprocess gets one shot at the whole response | Fixed via `llm._cli_timeout`, with `_is_long_call()` as the single predicate |
| D3 | **`paramiko` declared in no requirements file** | The whole "6. Run" step was dead on a fresh venv, and reported it as `"SSH connection failed"` — reads as a lab-network fault. This is why the bench probe had never passed. |
| D4 | **`lib2to3` removed from the stdlib in Python 3.13** — the version this project targets | D3 py2→py3 fragment translation had silently stopped (`status: "unavailable"`, 1 flagged fragment, 0 translated). Now falls back to `fissix`. |
| D5 | `claude -p` invoked with tools enabled — **an agent, not a completion** | 2,670,565 input tokens / 23 min / **$4.65** returning an **empty result**, `is_error: false`. Retry cost **$5.24** the same way. |
| D6 | The caller's `system` message was **dropped entirely** on the `claude_code` path | That transport alone ran unsteered |
| D7 | `_JSON_SYSTEM_PROMPT` ("no markdown fences") was sent to the two templates that ask for a **fenced python block**, which `_parse_generated_blocks` requires | The request argued with itself, on every backend |
| D8 | `gather_fragments` treated an **unparseable** reply as an **empty** one | Two cases recorded 0 reusable fragments while step 3 had selected 12 scripts — a wrong artefact wearing the face of a valid answer |
| D9 | The CLI's `result` field returns **only the final assistant message** | On a long answer the head is dropped, leaving a mid-class tail that lints as `IndentationError` and points nowhere near the transport. Fixed with `stream-json` + concatenation. |
| D10 | Thinking uncapped consumed the whole output budget | 31,100 thinking tokens with zero answer text. Capped — but see §3, the cap is per-block. |
| D11 | Passing `--max-thinking-tokens` **turns extended thinking on**, so applying it unconditionally slowed every call ~7x (2,242ms → 16,426ms) and **timed out the 30s health ping** | My own regression, caught immediately by the health check going red. Now scoped to long calls. |
| D12 | `pt_preflight` could not resolve a **topology-contract role** (`misc.get('ck_role_dut','swi_a')`), so it reported `UN-RUNNABLE (0/2 links)` — a confident wrong negative where the truth was "cannot determine" | Every script written to the new contract was un-checkable. Fixed; links went 0/2 → 1/2 with no regression on the pinned Port scripts. |
| **D13 OPEN** | **Generation over-declares a stack.** `init_stk('stk_a')` is emitted, assigned to `self.stk_a`, and never used — so the script demands a stack the case does not need and cannot run on any bench without one. | The 2026-07-30 minimality work made this "structurally impossible" for `init_swi` but **`init_stk` is not covered by the same constraint**, and no lint catches a device that is bound but never used. |
| **D14 OPEN** | **`pt_preflight` cannot follow `_ck_bind_link`.** The fixed frame resolves `ck_link_<role>` at run time, so preflight sees an unresolvable `init_portlink(dut, far)` and cannot issue a clean RUNNABLE verdict for any contract-based script. | Suggested fix: check the **contract** (does the bench declare `ck_link_<role>`?) via `pt_profiles.py`, rather than tracing into the helper. |
| **D15 OPEN** | **The fix loop can regress a good script.** `POST /fix_script` on a complete 37,744-char script returned 25,172 chars with **0 TestCase classes** and a new syntax error. | It only updates the session, so the on-disk file survived and `history/iter-1/` held the good copy — but a subsequent `save_script` would have shipped the regression. A fix pass that lints worse than its input should be rejected, not stored. |

## 5. Reproducing / continuing

`RESUME.md` has the full runbook. Shortest path:

```bash
curl -s -X POST localhost:8000/api/wizard/set_llm_config -H 'Content-Type: application/json' \
  -d '{"provider":"claude","auth_method":"claude_code","model":"claude-opus-5"}'
python3 tool/pt_autopilot.py --cases-file ask-ck/pytest-create/autopilot/batch-10.txt \
        --phase pytest --trim-verify 6 --run-dir ask-ck/pytest-create/autopilot/batch-01
python3 tool/pt_autopilot.py --cases-file ... --status     # compiles / lint_clean / trimmed
```

⚠️ `run.sh` always passes `--reload`, so **editing anything under `ask-ck/CK-main` bounces the
server and kills in-flight LLM calls**. Sequence server edits into idle windows. And this repo
is on NFS: `tail` can serve a minutes-stale view of a log, so read progress from `state.json`.
