One prompt, two models: where the tokens go over time

The identical ~400-line "generate a switch-port test script" prompt, sent to both org vLLM models over the new streaming transport. Both are reasoning models — the difference is what happens after the reasoning phase.

Streaming keeps the socket alive through the reasoning phase, so the HTTP read timeout now bounds the gap between chunks, not the whole response. That let the 35-minute run below complete at all — but completing is not the same as producing an answer.

What this means for the fix

  • Streaming did its job. The 35.8-minute call completed with no read-timeout — the old static ceiling (even the 600s floor) would have aborted it. The read budget is now per-chunk, so a reasoning phase of any length survives.
  • But it also exposed that vllm-thinking is unfit for large-output generation. It spent its entire 32,000-token budget on reasoning and emitted zero answer (finish=length). Streaming makes the transport robust — it does not make the thinking model practical.
  • Both are reasoning models. vllm-fast also reasons first (~21s of it here) — it just transitions to the answer. vllm-thinking never transitioned on this prompt. The vLLM SSE structure is identical for both; the divergence is reasoning-phase duration.
  • Decision holds: keep vllm-fast as the PyTest Creator default for generate_script-scale work. This confirms, rather than changes, the Part 2B recommendation.
