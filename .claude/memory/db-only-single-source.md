Terrence holds a firm product principle: **Ask-CK must be a stand-alone product with a single source of truth.** All corpus/reference lookups at runtime go to `ask-ck/var/ck.db` and NOWHERE else — no parallel JSON reads, no divergent second source. `ck.db` being gitignored is correct (it's a *derived, rebuildable cache* — `python3 tool/build_db.py --fresh` regenerates it byte-identically from tracked source exports; committing a 393 MB binary that rebuilds from inputs would bloat history and can't diff/merge). The LLM endpoint (`vllm.ai.atlnz.lc`) is NOT an "external dependency" — it's the tool's core function, scoped in. Unplanned inter-dependencies (like the huggingface model-load ping) ARE unwanted and were removed. See [[pending-approved-plans]].

**PLAN-db-only-search Phase 1 EXECUTED 2026-07-20 (uncommitted; Terrence commits himself).** Runtime is now strictly DB-only:
- `data.py load_all_data()`: 5 references repointed to db.* getters — `zephyr_master`→`db.get_target_cases()` (shape parity confirmed: identical 410 records, DB is superset adding issues/attachments), `candidates`/`candidates_dict`→`db.all_candidates()`, `decisions`→`db.get_decisions()`, `framework_surface`/`scripts_index_meta`→`db.get_json_doc(...)`. Deleted now-dead `load_json_safe`/`load_json_abs` + `json`/`os`/`BASE` imports.
- `routers/pytest_create.py` framework_surface validation read → `dbx.get_json_doc("framework_surface")` (db imported there as `dbx`, aliased to avoid a `db` param collision).
- `main.py` startup now FAILS FAST (RuntimeError with rebuild instructions) if `db.startup_check()` not ok — no JSON fallback exists anymore. Note: main.py imports `db` locally inside functions, not at module level.
- **Guard**: `tool/guard_db_only.py` greps CK_server/ for reads of retired corpus files (zephyr_cases.jsonl, *_master.json, candidates.json, decisions, framework_surface.json, scripts_*index*, etc.) and exits 1 if any reappear. Verified it both passes clean AND catches an injected regression. Run before committing DB-layer changes.

**Legitimately still file-backed (NOT corpora, correctly NOT flagged):** secrets (`secrets.local.json`, `secrets.testboxes.json`), static assets (`index.html`, `PROCESS.md`), per-case refined exports (`zephyr_payload.json`, `provenance.json`), debug logs (`llm-debug/*.jsonl`). The DB plan explicitly keeps refined-case exports + secrets as files.

**Why:** Terrence pushed back hard on "why is the DB gitignored / why are there other .json sources" — the single-source-of-truth invariant is a real requirement to him, not a nicety. Don't reintroduce a runtime JSON corpus read; if you must add corpus data, add it to the DB + a db.* getter and keep the guard green.

**2026-07-21 — the invariant also covers script SOURCE, not just corpus JSON.** Found + fixed a live violation: `routers/pytest_create.py::_read_source` was reading script code off the filesystem via `Path(rec["path"]).read_text()` — the old `testsuites_art/`/`svt_scripts/`/`test_scripts/` mount, which no longer exists on this host (only `DeviceSkrips/framework` + `copilot/` remain under `/mnt/testbox_home`). Script source lives in ck.db (`scripts.source_text`, 830 scripts); getter is `db.get_script_source(sid)`. Fix: `_read_source` now slices `rec["source_text"]` (already loaded by `db.get_script`) and falls back to `db.get_script_source(rec["id"])` — never disk. Removed the dead `TESTBOX_HOME`/`FRAMEWORK_LINT_PARENT` mount anchors. The `rec["path"]` field is now PROVENANCE-ONLY (records the original repo location; never dereferenced). **The guard had a blind spot** (it only grepped named corpus JSON files, not source-off-disk reads) — extended `tool/guard_db_only.py` with `SOURCE_PATH_RX` (flags `Path(rec["path"]).read_text()` etc.) + `RETIRED_MOUNT_RX` (flags `testsuites_art`/`svt_scripts`/mount-framework when used to reach the FS, but allows the word inside human-facing strings like the promotion instruction). Verified: guard catches an injected regression, `_read_source` returns 118-line DB source for the exemplar, live server `script_source` serves from DB. Terrence's directive: **no logical pointers/references to old mount or storage points — referenced data always comes from ck.db from now on.**
