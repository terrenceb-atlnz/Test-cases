**THREE bugs found + fixed this session (all uncommitted working-tree changes; Terrence commits himself):**
1. `build_db.py embed()` checked `db.HAS_VEC` BEFORE `get_connection()` (which sets it) → `--embed` had literally never run; that (not a missing dep) is why embeddings_meta was empty. Fix: open connection first, then gate.
2. `db.py _vector_hits()` ran the sqlite-vec KNN as a JOIN with outer `ORDER BY distance LIMIT ?` — sqlite-vec v0.1.9 REQUIRES the LIMIT/k on the vec0 table in the same query level as MATCH, else raises OperationalError which the `except: return []` swallowed → semantic search SILENTLY returned nothing (hybrid was keyword-only despite vectors existing). Fix: KNN in a subquery (LIMIT inside), then JOIN to hydrate. This is the highest-impact fix — semantic/hybrid search was dead in practice.
3. Embedding model was an unplanned external inter-dependency (sentence-transformers pings huggingface.co on model load even when cached). Terrence's directive: Ask-CK must be STAND-ALONE — depend on nothing external except its own LLM endpoint (routine model refresh doesn't count). Fix: force `HF_HUB_OFFLINE=1`/`TRANSFORMERS_OFFLINE=1` in both `db.py _get_model()` (os.environ.setdefault before import) and `run.sh` (exported, `:-1` overridable). Model bundled at `ask-ck/var/models/` (88 MB, loads offline, verified no network noise in server log). The LLM (vllm.ai.atlnz.lc) is NOT an external dep — it's the tool's core function, scoped in.
